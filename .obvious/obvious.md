# obvious.md — content-blocker

Agent guidance for `rishiv7/content-blocker`. Written by the autobuild onboarding run of 2026-09-24.

## What this repo is

Chrome extension (Manifest V3) that filters page text from one natural-language instruction. A local TrueForge agent compiles the instruction into a structured rule; Jev scores passages against it; matching text gets a clickable white cover. The extension ships as plain ES modules loaded unpacked from `extension/` — there is no server, database, or app build for the extension code itself.

## Stack

- **Runtime:** Chrome 120+ (MV3), vanilla JavaScript ES modules — no framework.
- **Tooling:** Node.js (engines `>=22.14.0`; jsdom 30.1.0 additionally requires `^22.22.2 || ^24.15.0 || >=26`), npm (only `package-lock.json` is tracked), esbuild 0.28.2 (bundles the TrueForge SDK), built-in `node:test` runner.
- **Dependency:** `@truefoundry/trueforge-sdk@0.2.0` (pinned), bundled locally for MV3.

## Commands

| Command | Purpose |
| --- | --- |
| `npm ci` | Install dependencies (40 packages). |
| `npm run build` | Rebuild `extension/vendor/trueforge-sdk.js` (esbuild bundle of the SDK). |
| `npm test` | All 63 unit/DOM tests (`node --test tests/*.test.js`; mocked APIs; no paid requests). |
| `npm run setup:trueforge` | Create/update the `content-blocker-compiler` agent on a running local TrueForge server. |
| `npm run test:live` | Optional live compile smoke test — needs TrueForge at `http://localhost:8790` with a configured model. |

## External services

- **TrueForge local server** (`http://localhost:8790`): required only to save/compile instructions and for `test:live`. Managed outside this repo (`~/.local/bin/trueforge`); not needed for build or tests. Existing filters keep working while it is stopped.
- **TypeSafe API** (`https://api.typesafe.ai`): runtime passage evaluation with the user's own key (entered in extension options). Not needed for build or tests.
- No Postgres/Redis/queues. No `.env` file; no required env vars. Optional `TRUEFORGE_MODEL` overrides the model in `setup:trueforge`.

## Sandbox setup notes (this environment)

## Gotchas

- Never hand-edit `extension/vendor/trueforge-sdk.js` — it is generated by `npm run build`.
- `bun.lock` present in the sandbox is untracked; this repo's package manager is npm.
- Failed/malformed/refused instruction compiles keep the previous rule active; saving an unchanged instruction reuses it without a model call.
- Tests deliberately mock all network APIs — a passing suite requires no keys and no TrueForge server.
